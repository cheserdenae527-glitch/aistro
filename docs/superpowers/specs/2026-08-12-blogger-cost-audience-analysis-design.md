## 1. 背景与目标

商家投放的核心问题不是"这个博主火不火"，而是：

1. **值不值**——花这个图文/视频报价，换来多少真实曝光与互动？
2. **准不准**——这个博主的受众，是不是我的目标消费层级的商家/顾客？
3. **真不真**——这个互动数据，到底是真实效果还是刷出来的？

本增量补齐三块：

- **性价比**：先过真实性闸门，再结合蒲公英官方报价 + 真实互动质量，输出 0–100 分、**商家建议出价**与**博主价值上限**两套价格。
- **受众画像**：从真实笔记文本推断受众消费层级、人均消费区间、品类与场景，并给出"适配哪类商家"的结论；反哺内容垂直度。
- **分层评价体系**：T1–T4 每个粉丝层级一套完整评价体系（互动基准/报价锚点/阅读率/画像解读/话术），正式化、配置化。

> **核心原则（v1.6 新增）**：性价比的一切计算必须建立在**真实性通过**的前提上。真实性闸门未通过 → 性价比不计分、不反推报价，绝不把刷量号"洗白"成高性价比。

## 2. 数据输入、口径声明与时间窗口

### 2.1 数据输入
| 数据 | 来源 | 用途 | 缺失处理 |
|---|---|---|---|
| 图文/视频/最低报价 | 蒲公英 `picture_price / video_price / lower_price` | 性价比 | 降级（§4.7） |
| 蒲公英中位数点击/互动 | `click_mid_num / inter_mid_num` | 曝光/互动估值（辅助） | 退化为粉丝×阅读率 |
| 粉丝摘要 | `fans_summary` | 曝光率校准 | 忽略 |
| 真实笔记文本 | `notes[].title + desc + tags` | 受众画像 | 画像降级 |
| 真实互动数据 | `notes[].stats` | 质量系数/CPM/CPE | — |
| 粉丝数/层级 | `follower_count` → T1–T4 | 分层评价 | — |
| 刷量检测结果 | v1.3 闸门2（fake_ratio/赞藏倒挂/水评） | **真实性闸门** | — |
| 商家目标层级（新增） | 前端传入 `merchant_profile` | 受众匹配 | 匹配判断降级为"展示不判定" |

### 2.2 口径声明（v1.6 修订，实施前必须与蒲公英接口文档核对后写死）
1. **点击 vs 阅读**：v1.5 把 `click_mid_num` 当"阅读量"用是口径混淆。**v1.6 明确**：
   - `click_mid_num` 是**中位数点击量**（用户点击进详情），`inter_mid_num` 是**中位数互动量**。
   - 曝光/阅读估值 `exposure_est` **优先使用蒲公英的"阅读/浏览"类字段**（实施前核对接口是否存在，如 `read_xxx` / `browse_xxx`）；**不存在时**用 `粉丝 × tier.read_rate` 估算，**不再把 click_mid_num 当阅读量**。
   - `click_mid_num` 仅作为辅助交叉参考（见 §4.3 交叉校验），不参与 CPM/建议报价主路径。
   - 文档与代码统一命名：`exposure_est`（阅读估值）、`click_mid`（点击中位数）、`inter_mid`（互动中位数），三者在代码里是不同变量，禁止混用。
2. **报价口径**：蒲公英 `picture_price / video_price` 若含平台服务费，实施前在配置里声明 `price_includes_platform_fee: true/false`；`suggested_bid` 统一按**商家到手价**口径输出，与 pgy 展示价并列展示时 UI 注明口径差异。
3. **时间窗口**：性价比、受众画像与 v1.3 五维**使用同一批真实样本**（同一任务抓取的 notes，近 90 天窗口），不另起抽样，避免模块间数据不一致。

## 3. 分层评价体系总则（Tier Matrix）

### 3.1 层级划分（沿用）
| 层级 | 粉丝区间 | 定位 |
|---|---|---|
| T1 | 1k – 1w | 本地达人 / 社区种草 |
| T2 | 1w – 10w | 区域达人 |
| T3 | 10w – 100w | 头部区域 / 腰部 KOL |
| T4 | 100w+ | 全国头部 KOL |

> **内部口径声明（v1.7）**：本系统 T1–T4 为**内部口径**，与行业惯用的头部/腰部/尾部命名**不完全对应**（行业常见：头部 >50 万、腰部 5 万–50 万、尾部 5 千–5 万）。对外沟通/文档引用时需注明"本系统分层为内部口径"，避免用词打架。

### 3.2 每层独立的能力基准（已上线）
加权互动率健康线 `min_healthy`、篇均收藏率健康线 `min_healthy_rate`、互动质量分档 `points`、涨粉基线 `growth_baseline`。

**分层绝对值门槛（v1.7 新增，双保险）**：相对互动率之外，各层加"篇均点赞/篇均赞藏绝对下限"，防止"互动率虚高但绝对量很小"的小号刷量（参考行业值，待标定）：

| 层级 | 篇均点赞下限 | 篇均赞藏下限 | 赞藏量级健康区间（篇均(赞+藏)/粉丝） |
|---|---|---|---|
| T1（<5k 粉） | 10 | 20 | [0.03, 0.15] |
| T1（≥5k 粉） | 20 | 40 | [0.02, 0.12] |
| T2 | 50 | 100 | [0.008, 0.06] |
| T3 | 500 | 1000 | [0.004, 0.025] |
| T4 | 3000 | 6000 | [0.002, 0.012] |

> 赞藏量级健康区间为**双向**且**按层配置（v1.8）**：互动率天然随粉丝量级衰减（大账号触达广、互动被稀释；小账号触达小圈层、互动集中），一套区间会系统性误伤大小账号。以上为**初值，必须用真实样本分布（P10/P25/P90）标定**（§10 分层标定项）。低于下界 = 数据太弱/疑似刷粉；高于上界 = 靠爆文撑数据、转粉率低、不稳定（§4.2 信号 2）。

### 3.3 每层独立的报价与性价比锚点（本次新增，待标定）
| 层级 | 图文中位报价 | 视频中位报价 | 预估阅读率 | 阅读单价(元/千) | 互动单价(元/个) |
|---|---|---|---|---|---|
| T1 | 500 | 800 | 15% | 30 | 2.5 |
| T2 | 1500 | 2500 | 10% | 40 | 3.5 |
| T3 | 4000 | 6500 | 6% | 50 | 5 |

> 锚点为初值，实施后用"相似创作者"接口真实报价做 P25/P50/P75 标定（§10）。

### 3.4 受众画像解读与商家适配（本次新增，**交叉映射表**）

`merchant_tiers` = 联合映射 `f(dominant_level, tier)`，两维都要：

| 受众层级 \ 粉丝层级 | T1 | T2 | T3 | T4 |
|---|---|---|---|---|
| **大众** | 街边/社区店 | 区域快餐/平价连锁 | 区域连锁快餐/大众品牌 | 全国大众品牌/连锁 |
| **中端** | 社区品质店/单店 | 商场店/区域连锁 | 连锁品牌/区域头部 | 全国中端品牌 |
| **高端** | 精品单店/预约制 | 商场中高端/精品连锁 | 区域头部/精品品牌 | 全国高端品牌/平台级 |
| **奢华** | （少见）小众高端 | 高端餐饮/奢侈体验 | 高端品牌/招商背书 | 头部品牌/平台级造势 |

> 示例：T3 + 大众 → 区域连锁快餐/大众品牌；T3 + 高端 → 区域头部/精品品牌。单看 tier 或单看受众层级都不完整，必须联合。

### 3.5 每层独立的合作建议话术（本次新增）
T1 偏"本地划算"，T4 偏"品牌溢价合理性"，话术配置化，避免误读。

## 4. 模块 A：性价比分析（cost_effectiveness）

### 4.1 目标
回答"按这个报价，值不值？真不真？"——输出 0–100 分、商家建议出价、博主价值上限、建议区间。

### 4.2 真实性闸门（v1.7 升级为**多维信号打分制**，计算流程第①步之前）

性价比与建议报价**必须先通过真实性闸门**。行业成熟做法是"多信号交叉验证 + 人工复核"，而非单一指标一票否——v1.7 从 v1.6 的三条硬规则扩展为**信号打分制**：每条信号命中记权重分，累计超过阈值判不通过；强信号仍可直接判。

```
信号清单（按数据可得性分三档）：

【A 档：现有数据即可用】
1. 刷量结构异常 fake_ratio > 阈值（沿用 v1.3 闸门2）           weight 30 —— 强信号，命中直接不通过
2. 赞藏量级双向异常（v1.8：区间按层配置，合并语义明确）        weight 20
   - 篇均(赞+藏)/粉丝 < 该层下界（数据太弱/疑似刷粉）
   - 篇均(赞+藏)/粉丝 > 该层上界（爆文撑数据、转粉率低、不稳定）
   - 藏/赞结构比 < 0.2（赞被单独刷，沿用 v1.3 倒挂）
   **合并计分（v1.8 明确）**：命中任一子条件即记满权重 20，**不叠加、不按比例**
   （低于下界与高于上界互斥，不会同时触发；藏/赞比<0.2 可与前两者并存，但权重仍只计一次）
3. 水评占比 ≥ 阈值（沿用 v1.3）                                 weight 15
4. 篇均点赞绝对值低于分层下限（§3.2，防"互动率虚高但绝对量小"） weight 10
5. 商单密度超分层阈值（v1.8：按层放宽 + 低权重）               weight 5
   —— pgy business_note_count / 总笔记 > 该层阈值
   —— 仅密度高不构成异常（T3/T4 专业商单达人 30-50% 占比属正常经营），
      权重低且按层放宽，避免系统性误伤头部达人

【B 档：with_comments 开启时可用】
6. 评论模板重复度高（v1.9 语义澄清）：短时间内大量【无语义模板短语】
   （"蹲链接""求推荐""已关注""支持""太棒了"等）→ 疑似机器互动  weight 15
   —— 必须排除【有真实问询意图的重复内容】："在哪""多少钱""求同款""怎么去""人均多少"
      （这些是高价值种草信号，与种草深度模块评论意向信号同源；误判会反噬种草评分）

【C 档：需蒲公英扩展接口（fans_profile / 流量来源 / 商单明细），实施后启用】
7. 同品牌重复合作 >3 次（v1.8 拆出，最精准的"刷榜换资源"信号） weight 10
   —— 需商单明细数据，实施前核对蒲公英接口是否提供
8. 点赞率区间异常（双向）：点赞/播放 ∉ [3%, 8%]（带货 ≤10%）
   ——过低=播放被刷高，过高=点赞被单独刷                      weight 0（占位）
9. 粉丝画像-内容一致性（v1.7 新增）：粉丝年龄/性别/地域画像
   与内容领域明显不符 → 粉丝构成存疑                          weight 0（占位）
10. 自然流量占比 < 65%（长期投流依赖）                         weight 0（占位）
```

```
判定与处理：
- 强信号 1 命中 → 直接真实性不通过（沿用 v1.3 闸门2 强制，不合作）
- 总权重分 ≥ 50 → 真实性不通过（非致命）：
    quality_q 强制 = 0；性价比 score = 0（detail.reason = authenticity_failed）
    decision 追加非致命红旗 authenticity_failed（进 caution 桶）
    suggested_bid / value_ceiling 输出 null，不反推报价
    UI 显示"数据真实性存疑，不提供报价参考"
- 总权重分 < 50 → 通过；detail 列出命中的子信号与分值，供人工参考
- 无 with_comments / 无蒲公英扩展数据时：B、C 档按 0 分处理，不阻塞
```

> v1.5 最大缺陷修正：**互动率达标度只能衡量"达标"，不能衡量"真实"**；真实性判断独立于互动率数字，且多维交叉验证降低单一规则误判率。

### 4.3 计算流程（真实性通过后）

```
① 质量系数 quality_q = clamp(0, 1, 加权互动率 / tier.min_healthy)

② 曝光估值 exposure_est
   优先：蒲公英阅读/浏览类字段（若有）
   否则：follower_count × tier.read_rate
   click_mid_num 仅作交叉参考（见⑦），不作阅读量

③ 单篇互动估值 engagement_est = exposure_est × 加权互动率

④ 市场参考价 fair_price(type) = tier.price_anchor(type) × (0.4 + 0.6 × quality_q)

⑤ 价格分 price_score：ratio = 报价 / fair_price → 锚点插值
   ratio ≤ 0.6 → 100；1.0 → 70；1.5 → 40；≥ 2.0 → 10

⑥ 质量门槛封顶：quality_q < 0.5 → 封顶 50；< 0.3 → 封顶 30

（图文/视频两种报价分别算出 sub-score 后合并为维度总分，规则见 §4.6 输出结构下方说明）

⑦ 交叉校验（v1.7 升级为分级阈值，参考行业"CPM 高于同类均值 2 倍以上即需警惕"）：
   用 click_mid 与 inter_mid 算平台侧 CPM_platform = 报价 / (click_mid/1000)，
   与主路径 CPM 比较：
   - 比值 > 2 倍 → audit_flag = "yellow"（提示口径/数据异常，建议人工复核）
   - 比值 > 5 倍 → audit_flag = "red"（强提醒，建议暂停合作直到澄清）
   评分正常输出，但 UI 展示审计标记。
```

### 4.4 CPM / CPE 定位（v1.6 明确）
- CPM（千人阅读成本）、CPE（单互动成本）**仅作展示参考，不直接参与 price_score**（price_score 走 fair_price 比值路径）。
- 文档明确写死这一句，避免实现/评审误以为"性价比分综合了 CPM"。
- CPM/CPE 的作用：① 展示给商家看成本结构；② 与平台侧 CPM_platform 交叉校验（§4.3⑦），不一致时触发人工复核标记。

### 4.5 建议报价（v1.6 修订为**双口径**，商家友好）

**口径定位**：
- `value_ceiling`（博主价值上限）：取 max(阅读价值, 互动价值) —— **谈判上限参考，博主视角**。
- `suggested_bid`（商家建议出价）：取加权平均并打商家友好折扣 —— **商家"能出的价"**，用于直接报价/砍价。

```
① 阅读价值 = exposure_est / 1000 × read_unit
② 互动价值 = engagement_est × inter_unit
③ 价值上限 value_ceiling = max(阅读价值, 互动价值) × 质量折扣 × 类型系数 × 市场融合
④ 商家建议出价 suggested_bid =
      (0.6 × 互动价值 + 0.4 × 阅读价值)   ← 加权平均，偏真实互动效果
      × 质量折扣 × 类型系数 × 市场融合 × 0.9   ← 商家友好折扣
⑤ 质量折扣（v1.6 修订，联动 hard_gate）：
   quality_q ≥ 0.5 → discount = 0.5 + 0.5 × quality_q
   quality_q < 0.5 → discount = 0.5 × quality_q（更陡，质量差报价压得更狠）
   quality_q < 0.3 → 两个价格均输出 null + 标注"数据质量不足，建议报价仅供参考"
⑥ 类型系数：图文 0.8 / 视频 1.0
⑦ 市场融合：0.7 × 数据反推 + 0.3 × tier 市场锚点
⑧ 输出区间：[suggested_bid × 0.85, suggested_bid × 1.15]
⑨ lower_price 联动（v1.6 新增）：
   若 suggested_bid < lower_price → 输出提示
   "博主自报底价 {lower_price} 高于系统建议 {suggested_bid}，可能不接受该价位，建议重新评估或放弃"
   若 suggested_bid ≥ lower_price → 正常，区间下限不低于 lower_price
```

**示例**：T2 博主，阅读估值 2.1 万，互动率 2.2%，quality_q=0.85
- 阅读价值 = 21×40 = 840；互动价值 = 462×3.5 = 1617
- value_ceiling（图文）= (1617×0.925×0.8)×0.7 + (1500×0.3) ≈ 1288
- suggested_bid（图文）= (0.6×1617+0.4×840)×0.925×0.8×0.7×0.9 + (1500×0.3×0.9) ≈ 1098 → 区间 [933, 1263]

## 5. 模块 B：受众画像分析（audience_profile）

### 5.1 目标
回答"这个博主的受众是什么消费层级的人？适配哪类商家？"

### 5.2 信号抽取（v1.6 修订：负面语义过滤 + 排除词典）

对每篇真实笔记的 `title + desc + tags` 依次做：

**第 0 步：负面语义前置过滤（v1.6 新增）**
- 命中负面词（`别、避雷、踩雷、不值、后悔、别去、劝退、差评、难吃、失望` 等）的笔记，**直接排除**，不计入任何价格/层级/品类信号（避雷/吐槽笔记是美食测评常见体裁，必须过滤）。

**① 价格信号（正则，配排除词典）**
- 匹配 `/人均|客单价|人均消费/{约}?(\d+)(?:[-~至](\d+))?元/`、`/¥(\d+)/`、`/(\d+)元\/位/`、`/(\d+)[-~](\d+)元/`
- **排除词典（v1.6 新增，命中即跳过该数字）**：`卡路里、热量、优惠、满减、减20、折扣、限量、库存、份、克、ml、秒杀、团购价` 等——防"满100减20""880卡路里""限量99份"污染人均区间。
- **同句判定（v1.10 产品行为定义）**：排除词**必须与价格数字在同一句**才生效；句界 = `。！？；换行`，**逗号不算句界**。
  例："人均80元，限量供应"（同句）→ 跳过 80；"人均80元。限量供应"（跨句）→ 保留 80。

**② 消费层级信号（词典）**
| 层级 | 关键词（示例，配置可扩） |
|---|---|
| 奢华 | 米其林、黑珍珠、omakase、fine dining、国宴 |
| 高端 | 法餐、私房菜、五星、预约制、人均500+ |
| 中端 | 商场、连锁、网红店、日料、西餐、brunch、烤肉店 |
| 大众 | 街边、小吃、食堂、夜市、苍蝇馆子、大排档、外卖、平价 |

**③ 品类与场景信号（词典）**
品类：火锅/烧烤/甜品/咖啡/奶茶/川菜/粤菜/日料/西餐/汉堡/面馆/烘焙…；场景：约会/聚餐/商务/亲子/夜宵/早餐/下午茶/一人食/探店打卡。

> **已知局限（v1.6 声明）**：基于文本规则，负面语义依赖第 0 步过滤，仍可能有漏判；先做 20–30 账号人工复核，再考虑引入评论信号增强（§10 分批迭代）。

### 5.3 聚合与输出
- 账号级分布：`level_distribution`、`dominant_level`、`avg_price_band`（P25–P75，基于过滤后价格信号）、`top_categories/top_scenes`、`merchant_tiers`（交叉映射 §3.4）。
- 置信度：有信号笔记数 < `min_signal_notes`（默认 5）→ `confidence=low`，仅展示、不参与评分。

### 5.4 与内容垂直度结合
垂直度 = **品类垂直度 × 0.7 + 受众层级集中度 × 0.3**（集中度 = dominant_level 占比，>70% 满分、<40% 低分，中间插值）。

## 6. 评分集成

### 6.1 维度构成（v1.6）
| 维度 | 权重 | 说明 |
|---|---|---|
| 种草深度 | 0.25 | |
| 内容垂直度 | 0.20 | 含受众画像深化 |
| 稳定产出 | 0.15 | |
| 持续经营 | 0.15 | |
| 增长趋势 | 0.15 | |
| 性价比 | 0.10 | 新增；真实性闸门未过/无报价时剔除并归一化 |

### 6.2 置信度归一化算法（v1.6 补齐公式）

```
dim_score[k] = 维度得分（None 表示无数据，剔除）
w[k] = 原始权重
w_eff[k] = 实际参与权重

规则（v1.11 澄清，与现状 growth_trend 行为对齐）：
- dim_score[k] is None（无数据）→ 剔除（不进分母，不参与总分）
  —— 如无报价的 cost_effectiveness、无快照且无内容趋势的 growth_trend
- dim_score[k] 存在 且 confidence ∈ {low, medium} → w_eff[k] = w[k] × 0.5
  —— 注意：low 但"有分数" ≠ 剔除（如无快照的 growth_trend 有内容趋势分数，
     保留分数、权重减半），仅 score=None 才剔除
- dim_score[k] 存在 且 confidence == high → w_eff[k] = w[k]
- 分母 = Σ w_eff[k] for k in S（S = 有分数维度）
- overall = Σ (dim_score[k] × w_eff[k]) / 分母

若 S 为空 → overall=None + score_suppressed=true（沿用）
```

### 6.3 输出结构变更汇总
- 新增 `dimensions.cost_effectiveness`
- 新增顶层 `audience`
- `dimensions.verticality.detail.audience`
- `decision.reasons/summary` 追加：性价比结论 + 建议报价（商家建议出价区间）+ 受众画像结论；真实性闸门未过时 summary 明确"数据真实性存疑，不提供报价参考"
- `insights` 追加降级提示

## 7. 商家目标层级输入与匹配（v1.6 新增）

### 7.1 `merchant_profile` 输入
前端在发起分析/批量筛选时可选传入（配置项，缺省为空）：
```json
"merchant_profile": {
  "target_price_band": [50, 200],   // 目标客单价区间（元）
  "target_categories": ["火锅", "烧烤"],  // 目标品类（可空）
  "target_merchant_tier": "中端",    // 大众/中端/高端/奢华（可空）
  "city_scope": "本地/区域/全国"      // 可空
}
```

### 7.2 匹配判定（v1.6 修订，不再用 tier 预期受众层级）
- `audience_match` = 匹配度 0–100，基于 **merchant_profile vs audience 画像**（权重：客单价 0.40 / 品类 0.25 / 层级 0.25 / 城市 0.10，缺项权重重分配）：
  - 客单价：`avg_price_band` 与 `target_price_band` 的重叠度（`overlap/union`）；
    **单点目标价（t1==t2）特殊分支（v1.12）**：点落在区间内（含边界）→100；区间外按 `(1 - 到最近边界距离/区间宽度)` 衰减——
    避免零宽度区间与任何区间"重叠长度恒为 0"的结构性失真
  - 品类：`top_categories` 与 `target_categories` 交集（命中数 / target 数）
  - 层级：`dominant_level` 与 `target_merchant_tier` 一致度（相同 100 / 相邻 60 / 隔一级 20 / 隔两级 0）
  - 城市：`city_scope` 与 tier 体量（本地/区域/全国）适配度；**T3 为双目标（区域/全国），命中任一即 100，
    否则按到最近期望值的序数距离（v1.12）**
- 无 merchant_profile 时：**只展示画像，不做匹配判定**（不生成 audience_mismatch）。
- **`audience_mismatch` 红旗修正（v1.6）**：仅在"有 merchant_profile 且匹配度 < 阈值"时触发；**废除"T4 头部博主画像全是大众=错配"的假设**——专注平价探店的人设是合法人设，是否错配完全取决于商家自己要投放的客群。

### 7.3 输出
`audience.match = { score, matched_level, mismatches: string[], has_profile: bool }`；有 profile 时 `decision.reasons` 追加匹配结论。

## 10. 风险与待标定项（含评审 C/D 类分批迭代）

1. **报价锚点/单价初值需标定**：用"相似创作者"接口拉同层真实报价做 P25/P50/P75 替换初值。
2. **字段口径需实施前核对**：蒲公英是否提供"阅读/浏览"字段、报价是否含平台服务费——直接决定 CPM 与建议报价正确性（A2/B6，评审前必须澄清）。
3. **真实性闸门效果验证**：用已知刷量样本回归测试，确认性价比/报价在刷量号上被正确压制（A1）。
4. **权重调整回测（v1.6 新增）**：0.30→0.25、0.20→0.15 的权重调整先用历史合作效果回测验证，遵循"先跑真实样本分布再定档"原则；未回测前标 `weights_pending_calibration`。
5. **受众画像误判（C8/C9）**：负面词过滤 + 排除词典先人工复核 20–30 账号；后续迭代引入评论信号增强（用户评论"人均/多少钱"）。
6. **商家目标层级（D12）**：merchant_profile 先做前端可选输入；默认缺省时系统只展示画像不判定匹配。
7. **CPM 口径交叉校验**：audit_flag 触发率上线后观察，异常率高说明曝光估值口径需修正；分级阈值（黄 2 倍/红 5 倍）按观察调整。
8. **分层参数统一标定（v1.8 合并）**：以下初值均需用真实样本分布（P10/P25/P90）按层校准，作为同一"分层标定"任务处理，避免各层参数互不联动：
   - 篇均赞/篇均赞藏绝对下限（§3.2，v1.7 引入）
   - 赞藏量级健康区间（§3.2 / §4.2 信号2，v1.8 改为按层配置，修正一刀切）
