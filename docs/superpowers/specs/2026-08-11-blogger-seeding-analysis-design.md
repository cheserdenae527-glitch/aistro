## 0. 设计目标

分数只回答一个问题：**这个餐饮博主的种草能力强不强，值不值得合作**。

- 种草能力 = 内容让人「想去吃 / 想安利」的能力：收藏（想去）、评论意向（想吃）、分享（安利）、转粉（关注）。
- 低质号识别独立于分数，用资格闸门一票否决（可不信的账号不给分）。
- 同一模型两种消费：单号深度报告看解释力，批量筛选看排序与硬门槛。

## 1. 行业调研结论（对比分析摘要）

调研来源：千瓜数据（达人指数/笔记传播指数/KOC 价值模型）、新榜（黄金三角）、天擎天拓（5 维雷达图/假量特征库）、Hashmeta（五维模型）、小红书 CES 公式与官方「真诚分」体系、2025 行业涨粉报告、多篇运营实操文章。

### 1.1 主流评估体系对比

| 体系 | 维度 / 权重 | 核心逻辑 |
|---|---|---|
| 千瓜达人指数 | 创作能力 50% + 粉丝活跃度 30% + 达人活跃度 20% | 创作能力 = 笔记互动 vs 同粉丝量级达人均值（分层归一化的行业依据） |
| 千瓜笔记传播指数 | (赞/均值)×1 + (藏/均值)×1 + (评/均值)×4 | 评论权重显著高于赞藏 |
| 千瓜 KOC 价值模型 | 超额互动(CPE<1) + 种草效果 + 转化效果 | 垂直度、评论区正面/产品词、@好友与分享异常 |
| 新榜黄金三角 | 互动率 + 涨粉率 + 完播率 | 互动率(赞评藏/粉丝)>8%、近30天涨粉率>3%、完播率>40% → 推荐概率高 2.3 倍 |
| 天擎天拓 5 维雷达图 | 互动深度 + 粉丝质量 + 内容垂直度 + 商业口碑 + 人设清晰度 | **收藏量才是种草力核心信号**；警惕高赞低藏/泛化评论刷量号 |
| Hashmeta 五维 | 互动率 25% + 粉丝量与增长 20% + 内容质量 20% + 画像匹配 20% + 商业配合 15% | 互动率+画像匹配合计 45% |
| 小红书 CES | 赞×1 + 藏×1 + 评×4 + 转×4 + 关注×8 | 关注(转粉)权重最高 |
| 官方 | 真诚分 / 健康等级 / 内容质量分权重 40% | 平台自己按账号分级扶优抑差 |

**共性结论**：没有体系把粉丝量当主权重；权重共识为「互动深度 > 内容稳定与垂直 > 涨粉 > 活跃度」，粉丝量只做分层基准。

### 1.2 关键指标基准（结构占位，待餐饮样本标定）

| 指标 | 行业基准 |
|---|---|
| 互动率(赞藏评/粉丝) | 1–3% 标准 / 3–8% 健康 / 8–12% 优秀 / 12%+ 顶尖 |
| 收藏率 | 3–5% 为优秀（收藏/阅读口径；我们无阅读量，改用 收藏/粉丝/篇） |
| 爆文率 | 10–20% 合格；优质账号 >20%（无阅读量，用互动量超中位数 3 倍口径） |
| 赞藏比(藏/赞) | 干货/探店 收藏>点赞；赞:藏≈2:1 正常，藏/赞<0.2 为异常信号 |
| 赞藏粉比 | 3–10 正常，>10 有爆文但转粉差 |
| 涨粉率(月) | >3% 健康（新榜）；分量级：<5w≈6%、5w–50w≈9%、50w–300w≈8%、300w–1000w≈10%、>1000w≈4% |
| 更新频率 | 每周 2–3 篇健康；<2 篇/周持续 3 个月 = 合作风险 +40% |

### 1.3 低质号 / 刷量特征库

| 类别 | 信号 |
|---|---|
| 刷量互动 | 互动率长期 <2%；赞藏比倒挂（高赞低藏）；通用水评；数据篇篇雷同；粉丝少但点赞异常高 |
| 粉丝注水 | 粉丝走势剧烈起伏/集中涌入后零互动；粉赞比失真；头像模糊/主页空白/无意义昵称 |
| 营销号 | 商单占比过高、评论区「广告取关」频繁、内容跨领域杂乱、更新机构化 |

## 2. 评分模型总览

```
种草能力总分 (0-100) = 五维加权
   ├─ 种草深度 30%   （收藏=想去、分享=安利、评论信号可选）
   ├─ 内容垂直度 20% （美食/探店内容占比）
   ├─ 稳定产出 20%   （爆文率 + 连续性/断崖）
   ├─ 持续经营 15%   （更新频率 + 新鲜度）
   └─ 增长趋势 15%   （涨粉率 + 内容互动趋势；无快照时降权标低置信）

叠加：资格闸门（一票否决，优先于分数）→ 账号阶段标签 → 合作建议
```

## 3. 数据准入与分层（沿用 C9 骨架）

- **真实样本**：详情抓取成功 + 赞/藏/评/转四字段齐全 + 有明确发布时间。缺失就是缺失，绝不估算、不外推。
- **粉丝分层**：T1 1k–1w（素人/KOC）、T2 1w–10w（初级/腰部）、T3 10w–100w（腰部/头部）、T4 ≥100w（头部/顶流）；互动率、收藏率、涨粉率的映射基准按层分别标定。
- **类型内标准化**：图文/视频按类型中位数归一，防混发账号被误判（探店类以图文为主）。
- **覆盖率可信度**（沿用 C9）：≥80% 且 ≥30 篇 = 高；≥50% 且 ≥15 篇 = 中；低于 = 低（不评分）。

## 4. 五维评分细则

> **插值口径（全局约定）**：本文所有分段锚点一律采用**锚点间线性插值**（与 C9 `_interpolate` 一致）；低于首个锚点取首个锚点分值，高于末个锚点取末个锚点分值。锚点值均为结构占位，待 §10 标定。

### 4.1 种草深度 — 30%（新增核心）

回答「内容让多少人想去/想安利」，餐饮口径：

```
收藏深度分 = 近90天篇均收藏 / 粉丝数，按粉丝分层映射（收藏 =「想去吃」最强信号）
分享扩散分 = 近90天篇均分享 / 粉丝数，按分层映射（最难伪造，抗刷）
评论信号分 = 评论参与度 = 评论数 / (赞+藏+评+转)；开启评论分析后升级为 意向词占比 − 水评占比（见 §9）

种草深度 = 收藏深度×0.45 + 分享扩散×0.30 + 评论信号×0.25
```

**赞藏比（藏/赞）不参与打分**——它本质与收藏深度同源（同一原始指标），若纳入打分会导致「刷收藏」同时拉高两项、并在总分中形成约 65% 的隐性收藏权重。赞藏比改作两类用途：
- **展示信号**：输出到 `dimensions.seeding_depth.detail.collect_like_ratio`，供人查看"干货 vs 泛娱乐"结构；
- **闸门红旗**：赞藏比中位数 <0.2 时触发刷量嫌疑判定（§6 闸门 2），而不是加分项。

**评论信号降权**：评论分析默认关闭时，"评论参与度"与真正"意向词占比"语义相差较大，该子项置 `confidence: low` 且权重 ×0.5 后与其余两项重新归一化（即 收藏≈51% / 分享≈34% / 评论≈15%）；开启评论分析后恢复全权重。

**边界**：收藏/分享中位数为 0 时该项按 0 计，由闸门兜底（刷量/倒挂）。

### 4.2 内容垂直度 — 20%（新增）

回答「是不是真正的美食/探店博主」：

```
每篇笔记用 标题+正文+标签 关键词判定是否餐饮相关
（探店/打卡/美食/好吃/菜单/套餐/口味/推荐/人气/排队/新店 等，关键词表入配置）
垂直度 = 餐饮相关笔记数 / 可判定笔记数
映射：≥80%→100，60%→70，40%→40，<20%→10
```

- 无法判定（无标题/正文/标签）的笔记不计入垂直度计算；可判定笔记数 < 真实样本数×80% 时，该维度置信度降为低。
- 升级路径：Phase 2 可换大模型分类（关键词表为 V1 实现，成本最低）。

### 4.3 稳定产出 — 20%（沿用 C9 骨架，改两处）

```
爆文判定 = 加权互动 ≥ 中位数 × 3（用中位数而非均值：均值会被少量刷量笔记拉高，
          导致爆文阈值虚高、真实优质笔记识别不出；中位数对异常值不敏感）
中位数为 0 时回退：均值 × 3 与绝对下限 200（行业小爆文口径）取较大者，避免全篇爆文

优质笔记占比 = 爆文数 / 真实样本数（行业合格线 10–20%）

稳健性子项（替代原 CV 波动项）：
  · 连续性 = 近30天是否存在 ≥14 天无发布的空白期（存在则扣分）
  · 断崖检测 = 最新30天 vs 前60天 标准化互动中位数下降 >50%（存在则扣分）
  稳健性 = 100 − 连续性扣分 − 断崖扣分（每项最多扣 25）

稳定产出 = 优质笔记占比分×0.7 + 稳健性×0.3
```

**为何弃用 CV**：优质笔记占比高的账号（稳定产出爆款）标准化互动方差天然偏大、CV 偏高，原公式会用 CV 反过来惩罚"有爆款"的账号，两个子项方向相悖。改为"连续性 + 断崖检测"只惩罚异常中断/暴跌，不与爆文率打架。标定阶段仍需验证两子项相关性（§10）。

### 4.4 持续经营 — 15%（沿用 C9）

```
发布频率分（近90天周均）：≥3→100，2→75，1→50，0.5→30，<0.5→0
新鲜度分（最新真实笔记发布距今）：≤7天→100，≤30→70，≤60→40，>60→0
持续经营 = 发布频率分×0.6 + 新鲜度分×0.4
```

`>60 天` 同时触发 §6 发布停滞闸门（维度降分 + 等级再降档）。

### 4.5 增长趋势 — 15%（原「趋势」升级）

```
涨粉率 = 近30天粉丝增长率（需 ≥2 个粉丝快照：订阅快照 + justoneapi 均可）
  分层基准（结构占位，行业参考月均）：T1≈6%，T2≈9%，T3≈8%，T4≈7%
  涨粉分映射：≥基准×1.2→100，基准→75，0.5×基准→45，≤0→15
内容趋势 = 近半程 / 前半程平均标准化互动（沿用原趋势逻辑，样本<10 跳过并归一权重）

有快照：增长趋势 = 涨粉分×0.7 + 内容趋势分×0.3
无快照：增长趋势 = 内容趋势分（**不使用阶段分补位**），维度 confidence=low，
        维度权重 ×0.5 后与其他维度重新归一化；总分置信度按 §7 通用规则汇总
```

**为何无快照时不引入阶段分**：无快照时阶段判定本身也依赖"互动趋势"推断（§5），若再让阶段分补位到 0.3 权重，等于同一份弱信号在维度内被计算两次，会制造"两个维度都指向成长期"的虚假一致性。因此无快照时增长趋势只保留内容趋势这一份信号，并显式降权 + 标低置信；阶段仅作独立输出标签，不进任何分数。

## 5. 账号阶段判定（独立输出标签，不参与加权）

| 阶段 | 判定信号 |
|---|---|
| 冷启动 | 粉丝 <5k，有更新但互动低、涨粉数据不足 |
| 成长 | 涨粉率 ≥ 分层基准，互动率爬升 |
| 成熟 | 涨粉放缓但互动稳定、内容垂直（最值得合作） |
| 衰退 | 涨粉率 ≤0 或显著低于基准 + 更新频率下降 + 互动下滑 |

- 有涨粉快照：按 涨粉率 vs 基准 + 更新频率 判定，置信度 high/medium。
- 无快照：按 粉丝量级 + 更新频率 + 互动趋势（近30天 vs 前60天）推断，**置信度恒为 low**，UI 须明示"推断"。
- 阶段只作为**独立输出标签**（解释性），不参与任何分数计算；仅在 §7 合作建议中使用，且置信度 low 时有限制（见 §7）。

## 6. 低质号闸门（一票否决，优先于分数）

| 优先级 | 闸门 | 判定 | 处理 |
|---|---|---|---|
| 1 | 数据覆盖率不达标 | §3 低可信度 | recommendation=`insufficient_data`，返回「数据不足，暂不评分」，不判定低质 |
| 2 | 刷量嫌疑 | C9 规则（点赞≥中位数×3 且 藏评转/赞<0.5%，命中>20%）+ **赞藏比中位数<0.2 且 篇均收藏/粉丝 低于该层最低健康线** + （可选）水评占比超阈值 | recommendation=`not_recommended`（强制「不合作」），`score_suppressed=true`，`low_quality=true` |
| 3 | 粉丝互动倒挂 | 篇均互动率低于该层最低健康线 | 等级封顶「待观察」 |
| 4 | 发布停滞 | 最新真实笔记发布距今 >60 天 | 等级降一档（**有意叠加**，见下注） |
| 5 | 涨粉异常 | 相邻快照增幅 >20% **且** 同期篇均互动率下降（僵尸粉信号） | 提示级红旗（不改等级） |

> **闸门 4 为有意叠加惩罚**：停更账号已在 §4.4 因新鲜度归零吃过维度分损失，等级再降一档是为了让「停更」这种硬伤比普通低分更显著；实现时不要因感觉重复扣分而去掉等级降档。
> **闸门 5 用「且」而非「或」**：纯涨粉（增幅 >20% 但互动率未掉）是 T1 小账号的正常有机增长（一篇小爆款即可周涨 20%+），不算红旗；标定时须专项验证 T1 层误报率，必要时按分层放宽阈值（如 T1 提至 35%）。

命中闸门 2 时**覆盖加权分数**：`overall.score = null` + `overall.score_suppressed = true`，直接输出强制结论 `not_recommended`；命中闸门 1 时同样 `score=null` 且 `recommendation=insufficient_data`。批量排序时 `score=null`（两种状态）的账号一律排最末，不参与正常分数排序。闸门结果写入 `decision.red_flags`。

## 7. 合作决策输出

**等级**（沿用）：≥85 卓越 / 70 优秀 / 55 良好 / 40 一般 / <40 待观察。

**合作建议**（`decision.recommendation` 取值，严格互斥，按下述顺序 if-elif 判定，先命中即止）：

| 取值（机器值） | 中文标签 | 判定（顺序执行） |
|---|---|---|
| `insufficient_data` | 数据不足 | 命中闸门 1（覆盖率不达标）：不评分、不判定低质 |
| `not_recommended` | 不合作 | 命中闸门 2（疑似刷量）：`score_suppressed=true`、`low_quality=true` |
| `priority` | 优先合作 | 总分 ≥70 且 **无任何红旗** 且 阶段∈{成长,成熟} 且 **阶段置信度非 low** |
| `ok` | 可合作 | 总分 ≥55 且 **无任何红旗（强制或非致命）** |
| `caution` | 谨慎 | 其余：总分 40–54，或存在非致命红旗（倒挂/停更/涨粉异常） |

说明：
- `insufficient_data` 与 `not_recommended` 是**两种不同性质**：前者是「没法判断」（抓取覆盖率不够，账号本身可能没问题），后者是「判断了、结论是别合作」。两者 `score` 均为 null、排最末，但 `low_quality` 只有后者为 true；`decision.summary` 必须写明具体原因，运营侧不得仅凭「不合作」标签拉黑账号。
- 非致命红旗（闸门 3/4/5 与提示级红旗）一律归入 `caution`；`ok` 显式要求无任何红旗，保证各取值互斥、可顺序判定。阶段置信度为 low 时最多进入 `ok`，避免弱推断被包装成强结论。

**输出结构**（一个引擎产出，两场景共用）：

```json
{
  "overall": { "score": 82.4, "level": "优秀", "description": "...", "score_suppressed": false },
```

**置信度汇总规则（通用，各维度小节不再单独定义）**：
- 维度置信度 ∈ {high, medium, low}；被跳过/降权的维度按 low 计（如增长趋势无快照、垂直度可判定样本不足、评论子项降权）。
- `overall.confidence = min(覆盖率可信度, min(五维度置信度))`；覆盖率可信度按 §3 映射（高/中/低 → high/medium/low）。
- 特例：若 low 仅来自单个非核心维度（垂直度/稳定产出/持续经营/增长趋势），且「种草深度」为 high/medium，则整体取 medium（避免单一弱信号过度拉低）。
- `grass_planting` / `growth_potential` 旧字段：保留输出但由新五维/阶段替代语义（兼容前端），后续前端切新字段后移除。

## 13. 风险与开放问题

1. **阈值标定**：所有百分比为结构占位，需真实餐饮账号样本标定后才能作为生产数字；未标定前评分结果应标注「初版阈值」。
2. **涨粉快照依赖与冷启动期**：涨粉率与阶段判定依赖 ≥2 次快照；无快照账号增长趋势维度降权标低置信，阶段仅推断且置信度恒为 low，因此「优先合作」在攒够第二次快照前**不可达**（属预期，避免弱推断冒充强结论）。快照随订阅刷新调度累积：订阅账号按刷新周期（通常数天）即有第二次快照，未订阅账号需先订阅；UI 对无快照账号显示「快照积累中」，运营需知悉系统上线头几周大部分账号最高只能到「可合作」。
3. **关键词表准确度**：美食垂直度 V1 依赖关键词表，可能漏判/误判（如探店文案不出现关键词）；Phase 2 用大模型分类兜底。
4. **评论抓取风控**：可选评论分析会放大请求量，需沿用 gate 节奏与失败降级（失败则回退到无评论信号，不影响主流程）。
5. **刷收藏对抗**：收藏是种草核心信号，也意味着刷收藏是主要攻击面；V1 用赞藏比闸门 + 收藏深度分双保险，标定时需用真实刷量样本验证区分度。
