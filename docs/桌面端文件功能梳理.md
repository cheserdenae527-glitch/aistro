# TWO 桌面端文件功能梳理（AiRestro 前端工作台）

> 整理日期：2026-08-08
> 范围：`D:\two\frontend`（AiRestro 餐饮商家 AI 运营工作台的“桌面端”，即浏览器访问的 React 单页应用）
> 目的：按功能脉络一步步梳理桌面端每个文件“是什么、属于哪个功能、和谁配合”，形成可直接查用的索引文档。

---

## 0. 一句话总览

TWO 桌面端 = **一个 React 18 + TypeScript + Vite + Ant Design 5 的单页应用**（`frontend/`），它通过 `src/services/*` 统一走 `/api/v1/*` 调 FastAPI 后端，按“商家 → 门店 → 平台账号/项目”的层级组织 10 大功能模块（总看板、商家管理、爬虫管理、账号装修、视觉设计、内容工坊、口碑管理、商圈分析、团购工坊、直播工坊）。

文件组织四层脉络：
1. **入口层**：`index.html → src/main.tsx → src/App.tsx`（路由 + 鉴权 + 顶栏菜单）
2. **页面层**：`src/pages/*`（每个功能模块一个“索引页 + 编辑器/详情页”）
3. **组件层**：`src/components/*`（页面内可复用的子面板/弹窗）
4. **数据层**：`src/services/*`（API 封装）+ `src/store/*`（全局状态）+ `src/utils/*`（纯函数逻辑）+ `src/types/*`（类型声明）

## 1. 技术栈与运行方式

| 项 | 说明 |

## 3. 全局骨架：入口 → 路由 → 鉴权 → 布局 → 数据请求

这一层是“功能脉络”的地基，所有模块都建立在它之上，按启动顺序梳理如下。

### 3.1 入口链

| 文件 | 作用 |
|---|---|
| `frontend/index.html` | 唯一 HTML 页面，标题“AiRestro · 餐饮运营工作台”，`<div id="root">` 挂载 `src/main.tsx` |
| `src/main.tsx` | React 根挂载：`ErrorBoundary`（全局错误边界）→ antd `ConfigProvider locale=zhCN`（中文 UI）→ `BrowserRouter` → `<App />` |
| `src/components/ErrorBoundary.tsx` | 类组件错误边界，页面崩溃时展示“页面出错了，请刷新重试”兜底 |
| `src/vite-env.d.ts` | Vite 客户端类型引用 |

### 3.2 路由与布局（`src/App.tsx`）

- 用 `lazy()` 按路由懒加载所有页面。
- `ProtectedRoute`：无 token 一律重定向 `/login`。
- `AppLayout`：顶部深色 `Header` + 横向 `Menu`（10 个一级菜单）+ `Content` 渲染子页面；`Dropdown` 显示当前用户、退出登录。
- 完整路由表（全部套 `ProtectedRoute + AppLayout`，`/login` 除外）：

| 路径 | 页面 | 功能模块 |

| `/` | DashboardPage | 总看板 |

| `/merchants/:id` | MerchantDetailPage | 商家管理（详情） |
| `/crawl` | CrawlJobsPage | 爬虫管理（含博主订阅/分析 Tab） |
| `/profile` | ProfileIndexPage | 账号装修（选门店） |

### 3.3 鉴权与 API 客户端

| 文件 | 作用 |
|---|---|
| `src/services/api.ts` | axios 实例（baseURL `/api/v1`，30s 超时）；请求拦截器自动带 `Bearer token`；响应拦截器 401 时清 localStorage 并跳 `/login`；同时 re-export `auth` |
| `src/services/auth.ts` | `User`/`LoginResponse` 类型 + `login/register/getMe/localLogin`（localLogin = 本机一键登录，供本地工作台免密进入） |
| `src/store/auth.ts` | Zustand 全局 auth 状态：token/user 持久化到 localStorage，`setAuth/logout/isAuthenticated` |

## 9. 维护与扩展指引（如何新增一个功能模块）

1. **新增 service**：在 `src/services/` 建 `xxx.ts`，复用 `services/api.ts` 的 axios 实例；类型（interface）与后端 schema 对齐。
2. **新增页面**：在 `src/pages/` 建 `XxxIndexPage.tsx`（列表）与 `XxxEditorPage.tsx`（编辑器），并在 `src/App.tsx` 注册路由 + 顶栏菜单项（`menuItems`）。
3. **拆子面板**：页面过大时把面板拆到 `src/components/xxx/` 子目录（参考 live/design/studio/deals/district 的既有惯例）。
4. **纯逻辑下沉**：把可单测的格式化/筛选/构建参数等纯函数放 `src/utils/xxx.ts`，并配 `xxx.test.ts`。
5. **全局状态**：仅跨页面共享状态才进 `src/store/`（如 auth、designJobs）。
6. **后端对接**：路由注册在 `backend/app/api/v1/__init__.py` 的 `routers` 列表；接口文档见 `docs/contracts/*-api.md`。
